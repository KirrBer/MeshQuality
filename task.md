# Задача: классификация качества 3D-мешей

## Описание задачи

Для обучения генеративных моделей, автоэнкодеров и других систем нужны качественные датасеты 3D-мешей: с гладкими поверхностями, без артефактов и странных дефектов. Данные, собранные из открытых источников, часто содержат низкополигональные, слишком простые, поврежденные или неполные объекты.

Требуется разработать модель машинного обучения, которая автоматически обнаруживает дефекты 3D-мешей и определяет, пригоден ли объект для дальнейшего обучения.

У одного объекта может быть несколько дефектов. Наличие хотя бы одного дефекта делает объект непригодным для обучения.

Помимо предсказаний, требуется предложить способ интерпретации решений модели: например, визуализацию отдельных областей меша, attention-карты на рендерах или другой объяснимый анализ.

## Что нужно предсказать

Для каждого объекта необходимо определить:

- `quality = 1` — хорошая модель;
- `quality = 0` — плохая модель;
- наличие каждого из десяти дефектов:
  `abstract`, `artifacts`, `intersection`, `lowpoly`, `noisy`, `open`, `partial`, `scale`, `set`, `simple`.

Файл `submission.csv` должен содержать те же поля, что и `train.csv`:

```text
item_id,abstract,artifacts,intersection,lowpoly,noisy,open,partial,scale,set,simple,quality
```

## Метрика

Итоговая метрика является взвешенной суммой двух F1-мер:

```text
f1_final = 10 * F1_quality + 10 * weighted_F1_artifacts
```

где:

- `F1_quality` — F1-мера для бинарной метки качества;
- `weighted_F1_artifacts` — взвешенная F1-мера для предсказаний дефектов.

Коэффициенты метрики: `w1 = 10`, `w2 = 10`.

## Данные

Доступны архивы:

- `train.zip` — обучающие данные и разметка;
- `test.zip` — тестовые данные без разметки.



### Файлы объекта

Для каждого `item_id` доступны:

- `{item_id}.png` — шесть изображений 3D-модели или сцены. Модель отцентрована и вписана в единичный куб. Используются четыре ракурса с шагом 90 градусов по азимуту, вид сверху и вид снизу.
- `{item_id}.npz` — данные 3D-модели. Файл содержит массив вершин `vertices` формы `(N, 3)` и массив граней `faces`.

### Таблица разметки

В `train.csv` для каждого `item_id` находятся бинарные значения `0` или `1`, показывающие наличие соответствующего дефекта и соответствие критерию качества.

## Дефекты

### `simple` — слишком простой объект

Геометрический примитив: куб, сфера, цилиндр или треугольник. К этому классу также относятся плоские объекты и выдавленные логотипы или изображения.

### `lowpoly` — низкополигональная модель

Полигонов недостаточно для передачи деталей. На гладких поверхностях заметны выраженные углы между полигонами.

### `noisy` — шумная поверхность

Поверхность состоит из шумных точек или полигонов. Такой дефект характерен, например, для 3D-сканов.

### `artifacts` — визуальные артефакты

На поверхности заметны странные переходы между треугольниками, пересечения или другие признаки повреждения объекта.

### `abstract` — абстрактная сцена

На сцене присутствуют 3D-надписи, графики, таблицы, схемы, диаграммы, опоры для 3D-печати или объекты в стиле Minecraft. Сцена не выглядит как единый осмысленный объект или композиция.

### `scale` — неподходящий масштаб

Объект занимает слишком малую часть кадра либо имеет неоптимальный масштаб, из-за чего детали неразличимы.

### `partial` — неполный обзор

Объект не виден с некоторых ракурсов: например, закрыт стеной, загородкой или плоскостью. Внутренние детали могут быть видны только с одного ракурса.

### `set` — несвязанные части

Сцена состоит из нескольких несвязанных частей или объект разделен в пространстве. Логически связанные объекты, например теннисная ракетка и мяч, сами по себе не считаются дефектом, если частей не слишком много.

### `open` — отсутствие объема

Объект полый внутри или состоит из плоских поверхностей, в том числе искривленных, без полноценного объема. Примеры: плоский скан, плоскость, закрывающая объект, или объект, из-за которого два ракурса почти пустые.

### `intersection` — сильное пересечение

Объекты на сцене сильно пересекаются либо один объект частично входит в объем другого.

## Критерий хорошей модели

Модель считается хорошей, если она не относится ни к одному из перечисленных классов дефектов. Хороший объект должен выглядеть визуально качественно, иметь гладкие поверхности и не содержать артефактов.
